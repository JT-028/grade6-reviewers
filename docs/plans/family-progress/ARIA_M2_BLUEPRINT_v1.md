Technical decisions:

- Transactional IndexedDB encryption/persistence follows the M1 private-cache boundary; no shared browser JavaScript. Server TypeScript and test utilities may be shared.
- GET reads use explicit allowlisted query fields; this requires an intentional parser change because M1 rejects every query string. Preserve existing route behavior elsewhere.

## 3. Identity, revisions, and grade rules

Subject enum: history, math, geography, language. module_key is the published filename stem without .html, e.g. Math6_Q2_Review_Module_v1.0.0. Quarter is integer 1 or 2, fixed by that file, never guessed from questions or calendar dates. Module/quarter/subject consistency comes from a catalog allowlist.

Stable assessment identity is (module_key, kind, set_key). For pop, set_key is the existing startPopQuiz(module) argument (flashcards/biomes/diagrams/tutor/cheat/practice as present in that reviewer); for exam it is exam-1 or exam-2 from examNum. Exam module_key is still the published reviewer, not a lesson section. Preserve required content constant names. Assessment ID is an opaque bounded text key derived from this tuple plus positive integer content_revision; it is not the published file version.

Important sampling interpretation: current pop quizzes sample a union of POP_QUIZZES and exam pools, and may transform items with varyQuestionFormat; both numbered exams sample the union of EXAM_SET_1 and EXAM_SET_2. The set label is not a guarantee of a fixed question list. content_revision versions the published source pool, answer keys, requested total, deduplication, format-generation policy, and scoring/grade policy for that set. Altering any of those increments the revision and creates a new catalog row. Reordering questions/options alone does not. Catalog digest uses canonical source items with correct answer meaning rather than shuffled answer index, plus policy versions and total.

administered_fingerprint separately hashes the sorted canonical administered item multiset, including generated True/False statement/correct answer semantics, excluding display order and mutable _answered fields. It records which random form was administered; it is NOT the comparison key. Thus independent samples from the same published revision remain comparable and retake trends remain useful. Wording can explain 'Same assessment version; questions may vary.' This interprets Rex's changed-questions rule as a published content/scoring change, not an ordinary random draw under the unchanged generator. Exact-form matching would make nearly all existing retakes First result, undermining requested trends. These are household learning trends, not statistically equated test forms; no claim of equal difficulty or tamper-proof grading is made. If product intent later requires identical forms, return that scope change to Rex before implementation; it is not a current blocker.

All eight inspected gradeFromScores implementations currently do: rounded_pct = Math.round(100 * correct / total), then rounded_pct >=90 Outstanding (O), >=85 Very Satisfactory (VS), >=80 Satisfactory (S), >=75 Fairly Satisfactory (FS), else Did Not Meet Expectations (DNME). Name this grade policy deped-descriptor-rounded-v1. There is no transmutation formula or separate numeric school grade in these files; do not invent one. Return descriptor, letter, and rounded_pct alongside the precise result percentage. Catalog pins the policy, so old rows never regrade after a future policy change. Example 17/20 = 85.00%, VS; 0/20 = 0.00%, DNME; a rounded threshold must match existing reviewer output.

## 6. Chronology, comparison, and selection ownership

completed_at is assessment finalization metadata, not M3 study-time tracking. Reliability policy: an online unlock/bootstrap server_time plus local request-start/response performance.now samples establishes a completion clock anchor only when round trip <=10 seconds and wall-versus-monotonic drift remains <=2 seconds. Derive completed_at from server epoch plus monotonic elapsed, conservatively mark unverified on navigation/reload without reanchor, sleep/discontinuity, absent server response, invalid clock, or authorization expiry. M2 fixtures provide synthetic anchors. Reject future timestamp >server_time+2min, invalid ISO or anchored completion outside source session issue/expiry window. completed_at can be null only for unknown quality; client_unverified can retain a reported date but cannot order trends. Server cannot independently prove offline clocks; this is trusted household telemetry, not exam attestation. No new study timer/idle measurement is needed.

Comparison key = child_id + module_key + subject + quarter + kind + set_key + content_revision (assessment_id resolves these). Sort eligible anchored completions by (completed_at,id) ascending; latest and immediately preceding are the last two. Stable tie-break is lowercase UUID byte order, independent of locale/receipt order. A third retake compares with second. A late anchored offline record may insert before/between/after and recomputes pairs; accepted scores never change.

For each subject and kind tile, select its latest anchored result across sets/revisions, then find prior ONLY within that latest result's key. Other sets are identifiable in paged detail. A new revision/set yields First result even when other sets have history. Never show a made-up single subject mean. When an unverified/unknown-time result exists within that subject/kind, it may actually be newest: keep dated rows visible but suppress directional subject summary (state null, chronology_unavailable) until chronology is resolvable; do not silently ignore it to claim an overall latest result. Matching sets unaffected by that unknown result may show their own comparisons in explicitly scoped detail. An isolated unknown result still is not First result. No automated time repair/regrading occurs in M2.

P=100*correct/total. pp=P_latest-P_prior. relative=100*(P_latest-P_prior)/P_prior. Compute before rounding; display percentages and pp to2 decimals, relative to1 decimal, half-up for nonnegative percent and sign-preserving half-up absolute deltas; normalize negative zero.
